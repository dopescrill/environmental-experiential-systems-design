## How Claude Code fits
Turn Figma concepts and service workflows into functional interfaces.

Claude Code builds things here while I learn the discipline. It does not replace the discipline. See [`../00_Learning-Plan/claude-code-in-the-curriculum.md`](../00_Learning-Plan/claude-code-in-the-curriculum.md).

### What I must understand myself
- The research behind the design: who the users are and what evidence supports each decision
- Journey maps and service blueprints: frontstage, backstage, support processes
- Interaction design patterns and when to break them
- Accessibility (WCAG) as a design requirement, not a final check
- The difference between a prototype that looks right and a service that works

### How to verify
- Usability-test the working interface with real or representative users
- Run an accessibility check (keyboard, contrast, screen reader basics)
- Compare the built flow step by step against the blueprint or Figma design
- Check every state: empty, loading, error, success

### Starter exercises
| Exercise | Build with Claude Code | Understand yourself | Verify |
|---|---|---|---|
| **Figma frame to working interface** | Claude Code turns a Figma frame into a working HTML/React screen. | Which design decisions are intentional vs placeholder. | Side-by-side comparison with the Figma frame; accessibility check. |
| **Service blueprint to working flow** | Claude Code builds a multi-step flow that follows a service blueprint, including backstage steps as stubs. | Blueprint layers; where the service can fail. | Walk each blueprint step through the built flow; test error states. |
| **Research synthesis support** | Claude Code helps organize interview notes into themes. | Synthesis is your judgment; AI clustering is only a starting point. | Re-read the source notes for each theme; drop any theme you can't trace to evidence. |
